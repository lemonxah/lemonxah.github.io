Struct ComponentRegistry

pub struct ComponentRegistry { /* private fields */ }
Expand description

Everything a game or plugin registers: components, systems and entities. One registry per app; plugins extend it through their zestengine_register export.

  • Components: register / register_ecs (name to factory and scene loader).
  • Systems: register_system, register_system_for, register_system_if, run by run_systems.
  • Entities (ready-made objects): register_entity.
ⓘ
#[unsafe(no_mangle)]
pub fn zestengine_register(registry: &mut ComponentRegistry) {
    registry.register_ecs::<Rotator>();
    registry.register_system_for::<Rotator>("game::rotate", Stage::Update, rotate);
    registry.register_entity("Spinner", spinner);
}

See Plugins in a project in the ECS guide.

pub fn register_ecs<T: TypedComponent + Send + Sync>(&mut self)

Register data for native ECS systems, retaining the same scene file, inspector and gizmo registration as an existing TypedComponent.

Call this for every component type a plugin adds, next to its systems. It is the same call as ComponentRegistry::register.

pub fn register_entity(&mut self, name: &'static str, build: EntityFn)

Register an entity: a named, ready-made object, described by a mesh shape and the components a new instance starts with. The editor lists it under Create > Entity, and systems spawn it by name with EcsMoveHost::spawn_entity.

build runs for every new instance, so each object gets its own component values. Names are unique: registering an existing name replaces the builder in place, so a hot-reloaded plugin supersedes its previous build, and a reload drops entities the plugin no longer registers.

ⓘ
fn crate_entity() -> EntityTemplate {
    EntityTemplate::new(EntityShape::Cube).with(Lifetime { seconds_left: 10.0 })
}
registry.register_entity("Crate", crate_entity);

See Entities in the ECS guide.

pub fn register_system( &mut self, name: &'static str, stage: Stage, run: SystemFn, )

Register a system that runs every time stage runs.

Names are unique: registering an existing name replaces the code and stage in place, which keeps execution order deterministic across hot reloads. Systems of one stage run in registration order, each seeing the previous one’s edits. Prefer register_system_for so unused features cost nothing.

ⓘ
registry.register_system("game::remove_the_dead", Stage::Gameplay, remove_the_dead);
Source

pub fn register_system_for<T: DataComponent>( &mut self, name: &'static str, stage: Stage, run: SystemFn, )

Register a system that runs only while at least one enabled T exists. Skipping also skips the stage’s hierarchy propagation and service set-up when no other system needs them, so features nobody uses cost nothing. This is the registration to reach for by default.

ⓘ
registry.register_system_for::<Health>("game::health", Stage::Gameplay, health);
Source

pub fn register_system_if( &mut self, name: &'static str, stage: Stage, run: SystemFn, condition: fn(&SystemWorld<'_>) -> bool, )

Register a system that runs only while condition(world) is true. The condition is evaluated every time the stage is considered, so keep it cheap. This is the tool for start-up work: run while any instance still needs initialising, then go quiet.

ⓘ
registry.register_system_if("game::door_start", Stage::Start, start_doors,
    |world| world.query::<&Door>().iter().any(|(_, door)| door.closed_y.is_none()));

pub fn run_systems( &self, stage: Stage, world: &SceneWorld, context: &mut SystemContext<'_>, )

Run every runnable system registered for stage, in registration order, over world. The engine calls this once per stage per frame; tests call it to drive systems headlessly. Commands the systems queue accumulate in context.commands; applying them is the caller’s job (the engine does it at the stage boundary).

Panics inside a system propagate after the world’s locks have been released.

pub fn register<T: TypedComponent>(&mut self)

Register a component type. Re-registering a name replaces the entry; that’s how hot-reloaded plugin components supersede their old build. Data is available to ECS queries; frame callbacks remain enabled. Use register_ecs when systems supply the type’s frame behaviour.
