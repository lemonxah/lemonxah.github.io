Avatar authoring components and the finished expression menu.

These components describe intent, not mechanism: a MenuToggle says “this menu entry shows or hides these things”; the avatar build pass (zestengine_assets::avatar_build) expands it into a parameter, a menu entry, an animation clip and a controller layer, on a clone of the avatar, and strips the authoring components from the result. Nothing here runs per frame.

Targets of actions are object paths below the avatar root (“” = the root itself, “Body/Hat” = a descendant), the same addressing animation clips use, so they survive renames done through the editor’s rename helpers and travel with prefabs.

AvatarMenu is the radial menu’s data: a tree of AvatarMenuItems with at most MAX_MENU_CONTROLS entries per page. The build pass assembles it from the hierarchy’s Avatar Menu Items and the generated toggles and stores it on the avatar root as AvatarMenuData.

AvatarMenu
The finished expression menu: the root page and everything below it.
AvatarMenuData
The avatar’s finished menu, written to the avatar root by the build pass. The radial menu reads it; there is nothing to edit here.
AvatarMenuNode
One entry of the finished menu with its page (Sub Menu only).
MenuInstaller
Installs an authored .avmenu page into the avatar’s menu without any manual wiring: drop it (with the prefab that owns the menu) anywhere under the avatar root and the page appears at install_to. Like Modular Avatar’s install target, an empty install_to is the menu root.
MenuToggle
A menu entry that shows or hides things. Put it on any object under the avatar root; one component builds the whole chain (see module docs).
MergeAnimator
Merge another animator controller into the avatar’s. Its parameters are renamed through the enclosing Avatar Parameters scopes, and clip paths are rebased onto the avatar.
MergeArmature
Merge this object’s bone hierarchy into the avatar’s: bones whose names match (after the prefix and suffix are removed) become one bone, the rest are re-parented with their world pose kept. Runs at package build only (it moves objects); in the editor’s Play the outfit stays separate.
ObjectToggle
Reactive object switch for prefab authors: it follows the nearest Avatar Menu Item above it (or on its own object), so dropping a prefab with a menu item and this component under an avatar is the whole install. A switched-off object (or component) never reacts.
ObjectToggleEntry
One object a reactive toggle switches.
SkinRebound
Written by the avatar build on every outfit mesh a Merge Armature merged: at load the runtime re-skins that mesh onto the skeleton of the avatar object avatar (bone indices rebound by humanoid bone, then name; bind poses corrected; extra bones appended or folded), and the avatar’s Animator poses it. The object keeps its own active flag, so a toggle that hides the outfit still hides it. Not an authoring component: it survives the build.
