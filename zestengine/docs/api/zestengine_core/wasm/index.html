Module wasm 

Source
Expand description

WASM components that expose callable functions (EVT-2): the WasmScript component hosts a sandboxed .wasm module whose declared actions and properties appear in the same event-binding dropdowns as the built-in Rust components (see crate::actions).

The older crate::Script component (env imports, start / update hooks) is a separate prototype and keeps working; this is the component ABI that bindings call into.

§Authoring a module

Compile for wasm32-unknown-unknown. The guest/zest-guest crate in the repository wraps everything below (manifest section, value codec, host imports, export glue) for Rust authors; the rest of this section is the exact contract it implements.

§Manifest

A custom section named zest_manifest holding UTF-8 RON (at most 64 KiB):

(
    name: "Door",                       // inspector title
    api: 1,                             // manifest version
    capabilities: ["state", "events"],  // host imports the module uses
    actions: [
        (name: "Open", label: "Open door", ugc_safe: true, params: [
            (name: "speed", ty: Float, default: Some(Float(2.0))),
        ]),
    ],
    properties: [(name: "state", ty: Int)],
)

ty is Bool, Int (i64), Float (f32), String, Vec3 or Object. A custom section was chosen over an exported function because the host, the package builder and the extractor can read it without running any guest code. The position of an action in actions is the action_index the host passes to zest_invoke; the position of a property is the index of zest_read_property. Names are what scenes store, so never rename a shipped action; indices may change freely between builds.

§Value encoding

All integers are little-endian. A value is a one-byte tag and a payload:

tagtypepayload
0Bool1 byte, 0 or 1
1Inti64, 8 bytes
2Floatf32, 4 bytes
3Stringu32 byte length (at most 16384), UTF-8 bytes
4Vec33 x f32, 12 bytes
5Objectu128 object id, 16 bytes, all zero = none

An argument block is a u32 count (at most 32) followed by that many values, in parameter order, at most 64 KiB in all. The host has already coerced each value to the declared parameter type and filled in defaults, so a guest can decode by position without checking tags. abi has the encoder and decoder.

§Host imports (module host, nothing else)

Pointers are i32 offsets into guest memory; strings are UTF-8 (ptr, len) pairs of at most 256 bytes. A bad pointer traps the call.

log(ptr, len)none32 lines per call, 512 bytes each
get_dt() -> f32, get_time() -> f32noneframe time and game time; the only clock
get_self(out_ptr)nonewrites the owner’s 16-byte object id
get_instigator(out_ptr) -> i32none16-byte id of whoever caused the event; 0 if none
get_float(ptr, len) -> f32, set_float(ptr, len, v)stateper-component named floats (64 keys)
emit_event(ptr, len)eventsbroadcasts an ActionEvent, 16 per call
get_property(obj_ptr, comp_ptr, comp_len, prop_ptr, prop_len, out_ptr, out_cap) -> i32readencoded value written to out_ptr, returns its length; an all-zero object means this one. Inside zest_update, and inside zest_invoke when the engine passes a world view (always in Play; -2 elsewhere, e.g. a test calling an action without one); -1 not found, -4 buffer too small. In zest_invoke the module’s own component is not readable, its sibling components and other objects are
invoke(obj_ptr, comp_ptr, comp_len, act_ptr, act_len, args_ptr, args_len) -> i32invokequeues a call of any component’s action (same type checks as a binding); it runs after the guest call returns, in the frame’s next command pass. 0 queued, -5 bad arguments, -4 queue full

A module may import only these. A host function whose capability the manifest doesn’t declare makes the module fail to load. There is no WASI, wall clock or randomness.

§Sandbox

  • The .wasm file is capped (SandboxLimits), its memory is capped in pages (declared and grown; growth past the cap fails with -1), and so is the guest call stack (deep recursion traps).
  • Every entry-point call, and instantiation, gets a fuel budget; running out terminates the call. The instance is reused across calls.
  • Any trap (fuel, stack, unreachable, bad pointer) disables the component: one error is logged, later calls do nothing, and the engine keeps running. Editing the file (hot reload) or changing the module field loads a fresh instance.
  • Imports are checked against the allowlist before instantiation.

§Trust

Modules inside an extracted content package are untrusted (register_untrusted_root). They get tighter limits, may not use the invoke capability, and expose an action to bindings only if its manifest flag ugc_safe is set and the package’s content limits allow module actions (ContentLimits::allow_wasm_actions). Project modules are trusted. See docs/user-content.md.

§Dynamic descriptors

Component::actions returns &'static [ActionDesc], so a module’s manifest is turned into such tables once per distinct manifest text and leaked (component interns them; at most 512 distinct manifests per process, then loading fails). Reloading an unchanged manifest reuses the tables.
