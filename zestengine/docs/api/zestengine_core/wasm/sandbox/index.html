zestengine_core::wasm

Module sandbox 

Source
Expand description

Loading and running one WASM component module inside the sandbox: static inspection (size, imports, memory, manifest section), the host import set with capability gating, and bounded calls (fuel, stack, memory).

code
Return codes of the host functions that return a status.

Structs§

HostState
The guest call’s host-side state: capabilities, limits and per-call budgets.
Instance
One instantiated module. Entry points are resolved once at load.

What static inspection learned about a module (nothing was run).
Outputs
What a call left behind for the engine to carry out.
PendingCall
An invoke request a guest queued; the component runs it with the engine context once the guest call returned.
SandboxLimits
Resource limits for one module, chosen by trust (see SandboxLimits::trusted).

Enums§

CallError
A call failed. A trap (fuel, stack, memory fault, unreachable) leaves the instance unusable; a failure is the guest saying “no” and is harmless.

Capabilities untrusted content may be granted: no invoke, so it can’t reach actions it wasn’t bound to.

Functions§

inspect_module
Check a module against limits and allowed capabilities without running any of it: size, host-only imports from the allowlist, one capped memory, a valid manifest, and that every import’s capability is declared (and allowed). Package building and extraction call this.
