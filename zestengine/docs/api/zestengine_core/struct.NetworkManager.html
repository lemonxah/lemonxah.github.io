Expand description

Session configuration for a scene: limits, the player prefab spawned for each peer, and optional auto-start for built games. The editor Network window and ctx.net_host read it.

Fields§

§session_name: String

Session name shown in server lists.

§port: u16

UDP port the session listens on.

§max_players: u32

Maximum number of peers (players) the session accepts.

§timeout: f32

Seconds without traffic before a peer counts as gone.

§discovery: bool

Answer LAN discovery queries while hosting.

§player_prefab: String

Spawned (owned by the peer) for every player that joins. Empty = none.

§spawn_tag: String

SpawnPoint tag player prefabs spawn at (round-robin).

§dedicated: bool

Old files: the host doesn’t get a player of its own. Read as topology: Dedicated (see NetworkManager::is_dedicated); no longer written.

§topology: Topology

Who runs the session: a player (ListenHost) or a dedicated server.

§validation: NetValidation

Server-side validation: limits, ownership rules, rate limits, strikes.

§anticheat: AntiCheatConfig

Anti-cheat provider and whether clients must pass it (SEC-2).

§interest: InterestConfig

Interest management for large worlds (off by default).

§clients_can_spawn: bool

Non-host peers may spawn networked prefabs.

§auto_start: NetAutoStart

Whether a built game starts networking on its own.

§address: String

Address Join auto-start connects to: host:port, or a room code (ABC123, via relay, or ABC123@relay.example.com:47800).

§relay: String

Relay server (host:port) for internet play without port forwarding. Hosting registers a room there too; empty = LAN / direct only.

§room_code: String

Room code a host asks the relay for (empty = the relay picks one).

§secret: String

Join secret: peers must know it to join, and it keys the session’s encryption. Empty = anyone who reaches the session can join.

§host_migration: bool

When the host leaves, the next player in line takes over and the session goes on (off = the session ends with its host).

§pin_host: bool

Clients remember the host’s identity for this address / room code and refuse a different one later (trust on first use).

§allow_list: Vec<String>

Only these player fingerprints may join (empty = anyone with the secret).

§ban_list: Vec<String>

Player fingerprints refused at the door.

§account_list: Vec<String>

Optional account logins (name:password, one per line). Empty keeps identity+secret-only auth.
