Module sprite_shape 

Source
Expand description

Sprite Shape (2D-8): a spline-driven sprite mesh. A closed spline is filled (a tiled texture or a stretched sprite) and every spline segment gets an edge sprite chosen by the direction the segment faces; sharp corners get corner sprites and an open spline can end in caps.

  • SpriteShapeRenderer (component): the spline (control points with in / out tangents, per-point height, corner flag and sprite variant), open or closed, the tessellation settings, sorting and the collider settings. It names a .spriteshape profile.
  • SpriteShapeProfile (asset, RON, extension SPRITE_SHAPE_EXTENSION): angle ranges mapping a segment’s normal angle to a list of edge sprites, corner and cap sprites, the fill texture.
  • spline: pure geometry (bezier tessellation with an error bound and a point cap, ear-clipping triangulation, polygon offset, Douglas-Peucker).
  • generate: spline + profile -> generate::ShapeMesh (position / UV / index groups, one per texture), and the collider outline.
  • edit: the spline edit operations the Scene-view tool applies, each with an exact inverse (pure model, unit tested).
  • presets: starter profiles and splines (grass strip, ground with fill, rope, road).

The engine gathers shapes in engine/src/scene/shape2d.rs: it rebuilds a shape only when SpriteShapeRenderer::content_hash or the profile changed and writes the groups into rewritable meshes of the sprite pool, so a scene with no shapes pays nothing. Behaviour follows the Unity Sprite Shape package as documented in docs/research/unity7/phase5b-2d-tilemaps-physics.md section 5; the code is our own.

Conventions: object-local XY plane, y up. A segment’s normal is the left of its travel direction; a closed spline is walked clockwise (a counter-clockwise one is reversed) so the normal points out of the shape. The angle of a segment is the normal’s angle from +Y, counter-clockwise, in degrees [0, 360): 0 faces up, 90 left, 180 down, 270 right.

Modules§

edit
Spline edit operations of the Scene-view tool, as a pure model: every operation applies to a SpriteShapeRenderer and returns its exact inverse, so an undo entry is just the inverse stored on a stack. (The editor also records the frame’s whole-component diff, so these are the testable core of what the tool does, not a second undo system.)
generate
Spline + profile -> sprite-shape mesh (2D-8), and the collider outline.
presets
Starter profiles and splines for Sprite Shapes. A preset fixes the structure (angle ranges, open or closed, fit mode, corner behaviour) and leaves the sprite slots empty: the sprites belong to the project, so the user drops theirs onto the slots afterwards.
spline
Pure geometry of sprite shapes: bezier tessellation with an error bound and a point cap, polygon area / orientation, ear-clipping triangulation, polygon offset and Douglas-Peucker simplification. No scene, no GPU.

Structs§

AngleRange
An angle range of a profile: segments whose normal angle falls in start..end (degrees, counter-clockwise from up, wrapping allowed: a range of -40..40 is the top) use the range’s sprites. Overlapping ranges: the higher order wins, then the earlier in the list.
ShapeHole
An inner closed spline that cuts a hole out of the fill of a closed shape (and gets its own edge sprites, facing into the hole, and its own collider path). Same tessellation settings as the outer spline. A hole should lie inside the outer outline and not overlap another hole.
ShapePoint
One control point of the spline. Tangents are offsets from position (the bezier handles), in object-local units.
SpriteShapeProfile
The .spriteshape asset.
SpriteShapeRenderer
The Sprite Shape component: spline + settings of one shape. Needs a .spriteshape profile for sprites; without one it draws nothing.
