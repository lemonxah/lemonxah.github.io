Sandboxed user-generated logic: the Script component.

A Script hosts one WebAssembly module (compiled by wasmtime) and calls its exported start / update hooks. The module sees only the narrow imported-function API below; no WASI is linked, so guest code has no file-system or network access. Execution is bounded per hook call with fuel, and linear-memory growth is capped.

Position/rotation/scale are the owning object’s local transform (the fields stored in ECS). The eight props are the component’s own numeric fields, so scripts have some per-object state. Reads happen against a copy written into the store before each hook and written back afterwards, so a trap leaves the object unchanged.

§Module format

The module field is a path to a .wasm binary. Content packages have packaged paths rewritten to absolute extraction paths at load time (see docs/user-content.md); base-game scenes resolve relative to the process working directory. The module must export at least one of start or update (both () -> ()).
