Expand description

Everything a system needs besides the world: time, input, the command queue and the engine services for this frame.

Systems edit component data directly and ask for everything else by pushing a ComponentCommand (or calling a helper such as SystemContext::emit). The engine applies queued commands, in order, when the stage ends.

Inside run_ordered you work through an ObjectContext, which dereferences to this type: obj.dt, obj.input and obj.emit(..) all work.

ⓘ
fn tick(world: &SystemWorld<'_>, ctx: &mut SystemContext<'_>) {
    let speed = ctx.input.axis2("Move").length() * ctx.dt;       // time and input
    ctx.commands.push(ComponentCommand::Quit);                    // a queued command
    ctx.emit(LevelComplete);                                      // visible next frame
}

See SystemContext in the ECS guide.

Fields§

§dt: f32

Seconds this frame, scaled by the time scale (0 while paused). In Stage::FixedUpdate this is the fixed step, 1/60 s. A single frame is clamped to 0.25 s so a hitch cannot teleport everything.

§unscaled_dt: f32

Seconds this frame ignoring the time scale: use it for pause menus and UI that must keep running while the game is paused.

§time: f32

Scaled seconds since Play started.

§water_time: f32

The shared water clock. Networked clients agree on it, which is what makes wave riders and floating bodies deterministic.

§input: &'a InputState

This frame’s snapshot of the player’s actions (down, pressed, axis2, …).

§commands: &'a mut Vec<ComponentCommand>

The command queue. Push ComponentCommands here; they are applied after the stage in the order pushed. A command naming an object that no longer exists is ignored.

§services: SystemServices<'a>

Borrowed engine services (physics, navigation, network, screen, …) and the event streams.

pub fn new( input: &'a InputState, commands: &'a mut Vec<ComponentCommand>, ) -> Self

A context with zero time and no services, over the given input and command queue. The starting point for tests and tools; set dt, time and the services you need.

Source

pub fn events<E: Any>(&self) -> impl Iterator<Item = &'a E> + use<'a, E>

The events of type E that were emitted during the previous frame, in emission order. Events of other types are skipped. The iterator does not borrow the context, so you can call SystemContext::emit while looping.

ⓘ
for hit in ctx.events::<Hit>() {
    total += hit.amount;
}
Source

pub fn emit<E: Any>(&mut self, event: E)

Broadcast event (any 'static type) to every system. It becomes readable through SystemContext::events in the next frame, never in this one, so a sender cannot react to its own event within the frame.

ⓘ
ctx.emit(Died { object: me });
Source

pub fn is_active(&self, world: &SystemWorld<'_>, entity: Entity) -> bool

Whether entity should run: its Active flag is set (enabled, and every ancestor enabled) and it is visible in the scene. Check this before acting for an object; disabled objects must not update.

Source

pub fn is_visible(&self, world: &SystemWorld<'_>, entity: Entity) -> bool

Whether entity is an object of the scene being run. Hidden or foreign objects (for example, ones not in the scene’s authoring order) are not visible, and the object helpers treat them as absent.

Source

pub fn order_key( &self, world: &SystemWorld<'_>, entity: Entity, ) -> (usize, u128)

A sort key that puts objects in scene (authoring) order, ties broken by saved id. Sort by it whenever the order in which objects act can change the outcome.

Source

pub fn instance_order<T: DataComponent>( &self, world: &SystemWorld<'_>, owner: Entity, instance: Entity, ) -> ((usize, u128), usize, u64)

A sort key for one instance of component T: object order, then the instance’s position among the object’s components, then entity bits. It keeps duplicate instances of a type in inspector order.
