Expand description

Everything a native game system can do to the world, bound to one object (called “self” below).

A native system is a function the engine runs once per frame stage (Stage). The usual way to write one is run_ordered: it calls your closure once for every active instance of a component, in the scene’s authoring order, and passes it the component (&mut T) plus an ObjectContext bound to the object that owns that instance. Through it you read and edit other objects, move things, spawn and destroy, push physics bodies, play sounds, save, switch scenes and use the network.

Guides: the Engine API Guide walks through this type by task (moving things, spawning and destroying, physics, input, audio, networking, with recipes), and the ECS Guide explains where it fits in the system model.

ⓘ
use zestengine_core::ecs::{ObjectContext, Stage, SystemContext, SystemWorld, run_ordered};
use zestengine_core::{ComponentRegistry, MotionContext, ObjectRef, TypedComponent};

#[derive(Default, Serialize, Deserialize)]
struct Chaser { target: ObjectRef, speed: f32 }
impl TypedComponent for Chaser { const NAME: &'static str = "Chaser"; }

fn chase(world: &SystemWorld<'_>, ctx: &mut SystemContext<'_>) {
    run_ordered(world, ctx, |chaser: &mut Chaser, obj: &mut ObjectContext<'_, '_>| {
        // World position of the target, or None when the reference is unset or the object is gone.
        let Some(goal) = obj.position_of(chaser.target) else { return };
        let here = obj.world_position();                        // `MotionContext`: world position of self
        let step = (goal - here).normalize_or_zero() * chaser.speed * obj.dt; // `dt` comes from `SystemContext`
        obj.set_world_position(here + step);                    // immediate: later systems see the move
    });
}

fn register(registry: &mut ComponentRegistry) {
    registry.register_ecs::<Chaser>();
    registry.register_system_for::<Chaser>("game::chase", Stage::Update, chase);
}

§What a call does, and when

Every method is one of three kinds, and its documentation says which one it is.

KindWhich methodsWhen you see the result
ImmediateReads, and writes that edit native component data in place: edit, set_local_transform, set_world_transform_of, set_world_position_of, set_destination, stop_agent, emit_particles, the local copy written by set_net_var, and the MotionContext setters such as set_translation and set_animator_bool.At once: on the next line, and in every system that runs later in the same stage.
QueuedAnything that pushes a ComponentCommand for the engine: spawning, destroy, set_active, add_impulse, set_velocity, move_character, sounds, saves, modify_material, time scale, language, and the local half of networked spawns.When the current stage is over. The engine applies the queued commands in the order they were pushed, after every system of the stage has run and before the next stage starts.
Queued (obj)Commands the play session does not handle itself but returns to the application hosting the game (the player or the editor): scene loads, quit, cursor lock, input rebinding, RPCs, ownership requests, and the replication half of networked spawns and variables.After the frame’s last stage. The host applies them at the end of the frame.

Spawn methods return the new ObjectId immediately, but the object only exists once its command has been applied, which is the next stage. Until then reads such as get or transform_of find nothing for that id. Commands you queue after a spawn and aim at the new id (for example set_active) are applied after it, in order, and do find it. Physics is the exception: a rigid body is created at the next physics sync, so an impulse or velocity aimed at an object spawned (or re-enabled) in the same stage is silently dropped.

§Frame order

A frame runs these stages in order. A system sees everything systems of earlier stages did, because queued commands are applied between stages.

  1. Start: objects that just became active run their start-up systems (once per object).
  2. FixedUpdate: zero or more times per frame at a fixed time step, each followed by a physics step.
  3. Events: collision, trigger and animation-event callbacks.
  4. Update, then Gameplay, then LateUpdate. The commands of Update are applied before Gameplay runs, so weapons, cameras and the like see positions after movement and physics corrections. Navigation agents and animation advance between Gameplay and LateUpdate.

See Stage for the stage list. Systems of one stage run one after another (never in parallel), so an immediate write by an earlier system is visible to a later one.

§Targets

Methods that act on another object take impl Into<ObjectRef>: an ObjectRef (the field type you put on a component and wire up in the inspector) or a bare ObjectId. A few methods take an ObjectRef only, because they predate this convention; their docs say so, and an ObjectId converts with .into().

  • Reads and in-place edits resolve the target with entity_of. An unset reference, an id no object has (never spawned, already destroyed, or spawned this stage and not applied yet), or an entity that is not a scene object gives None, false or a no-op; it is not an error.
  • Queued methods only check that the reference is set. The object is looked up when the command is applied; if it has gone by then, the command does nothing.
  • A disabled (inactive) object is still a valid target for reads and edits. Use is_active to ask whether it is running.

§Local and world space

translation, rotation and scale (from MotionContext) are the object’s own local values, relative to its parent. self_transform, transform_of, matrix_of, position_of and world_position are world values. The set_world_* methods take world values and convert them through the parent chain; set_local_transform writes the local fields directly. World values are computed from the live local transforms, so they include moves made earlier in the same stage.

§Borrow rules

Component data is borrowed with hecs’ checked borrows, one component column at a time. Asking for a component type that is already mutably borrowed panics (hecs reports already borrowed). The usual way to trigger that:

  • requesting the same component type T that the running run_ordered system is iterating, for example ctx.get::<Health>(other) from inside a Health system (the system already holds &mut Health);
  • calling edit for a type while a Ref guard of that type from get is still alive.

Read sibling components of other types, copy what you need out of a guard and drop it, or collect ids first and act afterwards.

§What you get through Deref

ObjectContext derefs (also mutably) to SystemContext, so the frame’s data is available on the context itself:

  • dt: seconds this stage advances game time, scaled by the time scale (the fixed step during FixedUpdate); unscaled_dt: real seconds, unaffected by set_time_scale, for UI and pause menus.
  • time: scaled game seconds since play began; water_time: the water animation clock (synchronised between peers in a network game).
  • input: this frame’s InputState, for example ctx.input.down("Fire"), pressed, released, axis, axis2 and mouse_delta.
  • commands: the command queue itself. Push a ComponentCommand directly for anything that has no helper here, such as ComponentCommand::AddForce, ComponentCommand::PlayAudio, ComponentCommand::AssignMaterial, ComponentCommand::NetDespawn or ComponentCommand::NetLoadScene.
  • services: the borrowed frame services (SystemServices: physics, nav, net, screen, materials, save, strings, time_scale, events, scene_events, …). The helpers on this type wrap them and fall back to None, false or a default when a service is missing, as in a headless run.
  • events::<E>(): the events of type E emitted during the previous frame, and emit: queue an event that every system reads next frame.
  • is_visible, order_key and instance_order: lower-level helpers for hand-written queries. (SystemContext::is_active takes a world and an entity; the context’s own is_active takes an object reference and shadows it.)

§Networking

Authority is the right to simulate an object and publish its state. In a session it belongs to the object’s owner peer, or to the host for an object nobody owns; see has_authority. A copy that another peer simulates is driven remotely (driven_remotely): local input must not move it. Offline (no session) every networking method behaves as local: you have authority over everything, connected, is_server and is_client are false, local_peer is 0, networked spawns create a plain local object, and rpc_self loops back to the caller.

  • State: connected, is_server, is_client, local_peer, peers, net_view, has_authority, driven_remotely.
  • Ownership: request_ownership_of.
  • Variables and calls: set_net_var, set_net_var_self, rpc_self, rpcs_for_self.
  • Spawning: net_spawn, net_spawn_server, net_clone, net_spawn_with.

§world: &'world SystemWorld<'world>

The ECS world this system call runs against.

Use it for direct component access to the owner (obj.world.get::<T>(obj.owner)) or for custom world.query loops. Unlike get and edit it applies no visibility check. The same borrow rules apply: see “Borrow rules” on ObjectContext.

§owner: Entity

The object this context acts for (“self”): the object that owns the component instance being updated.

This is a hecs handle, valid for the current call only. Use self_id when you need a persistent ObjectId to store or compare.

Binds a context to the object owner for the duration of one system call.

Game code rarely calls this: run_ordered builds one context per active component instance. Build your own in tests, or when a system walks objects by hand with world.query, passing the SystemContext the engine gave you.

pub fn driven_remotely(&self) -> bool

Whether another peer, not this machine, is currently simulating this object.

True only when all of these hold: a network session is connected, the object has a NetworkObject or Sync component, and the local peer lacks authority over it. Input-driven systems (character controllers, weapons) return early when this is true, so the local keyboard does not move a copy that belongs to someone else.

Immediate. Always false offline and for objects that are not networked.

pub fn self_transform(&self) -> Transform

The world transform of this object (position, rotation and scale decomposed from its world matrix).

Immediate. Computed from the live local transforms, so it includes moves made earlier in this stage by you or by other systems. For the local fields use translation, rotation and scale; for just the world position, world_position.

pub fn entity_of(&self, target: impl Into<ObjectRef>) -> Option<Entity>

Resolves an object reference to its ECS Entity, or None if the object cannot be used.

This is the gate in front of get, edit, transform_of, is_active and the other read and edit methods. It returns None when

  • the reference is unset;
  • no object has that id (never spawned, already destroyed, or spawned this stage and not applied yet);
  • the entity is not visible. Visible means the entity is a scene object (it carries an ObjectId) and, when the scene supplies an authoring order, is listed in it. The helper entities that hold the second and later copy of a duplicated component are not objects and never resolve.

Visible does not mean active: a disabled object resolves normally; ask is_active whether it runs. The returned Entity is a runtime handle for this call only; store ObjectId or ObjectRef values instead.

pub fn get<T: DataComponent>( &self, target: impl Into<ObjectRef>, ) -> Option<Ref<'_, T>>

Reads component T of another object.

Returns a checked borrow guard (Ref, which derefs to &T) for the object’s primary instance of T, or None if the target does not resolve (see entity_of), has no T, or has its T switched off. Additional duplicate instances of T on the same object are not reachable through get.

Immediate. It sees every in-place edit made earlier in this stage. Keep the guard short-lived: it holds a shared borrow, so editing or mutably borrowing the same component type while it is alive panics (see “Borrow rules” on ObjectContext). Copy out what you need and let the guard drop.

§Examples
ⓘ
// Read, then release the borrow before doing anything else with the context.
let hp = ctx.get::<Health>(self.target).map(|health| health.current);
if hp.is_some_and(|hp| hp < 10.0) {
    ctx.play_sound_at("audio/low_health.wav", ctx.self_transform().translation, 1.0);
}

pub fn get_self<T: DataComponent>(&self) -> Option<Ref<'_, T>>

Reads component T of this object, without the visibility check of get.

Returns None if the object has no enabled T. Immediate.

Use it for sibling components of a different type than the one your system iterates. Never ask for that type itself: run_ordered already holds &mut T for it, and a second borrow of the same type panics.

pub fn edit<T: DataComponent>( &self, target: impl Into<ObjectRef>, edit: impl FnOnce(&mut T), ) -> bool

Changes component T of another object in place by running edit on it.

Returns true if the closure ran, false if the target does not resolve (see entity_of) or has no enabled T.

Immediate. The closure runs before edit returns, with exclusive access to the live data, and later systems of the same stage see the result. Nothing is queued. The closure only receives the component, so compute anything that needs the context beforehand. Panics if T is already borrowed (see “Borrow rules” on ObjectContext), for example while you hold a Ref of the same type from get.

§Examples
ⓘ
// Hurt whatever the ray hit, if it has Health.
let damage = 25.0;
let hurt = ctx.edit::<Health>(hit.object, move |health| { health.apply_damage(damage); });

pub fn matrix_of(&self, target: impl Into<ObjectRef>) -> Option<Mat4>

The world matrix of an object: its own local transform multiplied through all of its ancestors.

Immediate. None if the target does not resolve or its parent chain is malformed (a cycle). Computed from the live local transforms, so it includes moves made earlier in this stage. See transform_of for the decomposed form and position_of for just the translation.

§Examples
ⓘ
// Where is a point that sits 0.5 m in front of the target, in world space?
if let Some(world) = ctx.matrix_of(self.target) {
    let muzzle = world.transform_point3(Vec3::new(0.0, 0.2, -0.5));
}

pub fn transform_of(&self, target: impl Into<ObjectRef>) -> Option<Transform>

The world translation, rotation and scale of an object, decomposed from its world matrix.

Immediate. None if the target does not resolve (see entity_of). Includes moves made earlier in this stage. The scale is the accumulated world scale; a parent with non-uniform scale above a rotated child cannot be represented exactly and loses any shear. For the object’s local values read the Transform component with get.

§Examples
ⓘ
// How far away, in world space, is the target?
let Some(target) = ctx.transform_of(self.target) else { return };
let distance = (target.translation - ctx.self_transform().translation).length();

pub fn objects_with<T: DataComponent>(&self) -> Vec<ObjectId>

Every object that has an enabled component T, as ids in authoring order.

Use it to find “all enemies” or “all spawn markers” without holding a reference to each. Only object roots are returned: an object appears once even if it carries several copies of T. Objects whose copy of T is switched off are not included.

Immediate. The list is a fresh Vec built from the world as it is now: objects spawned this stage are not in it, objects destroyed this stage still are (until the boundary). Disabled (inactive) objects are included; filter with is_active to keep only running ones. The order is the scene’s authoring order with the saved id as tie-break, so results are deterministic. It scans every object that has T; cache the result if you need it every frame in a large scene.

§Examples
ⓘ
// Count the enemies still running.
let alive = ctx.objects_with::<Enemy>().into_iter().filter(|id| ctx.is_active(*id)).count();

pub fn is_active(&self, target: impl Into<ObjectRef>) -> bool

Whether the object is running: enabled itself and under no disabled ancestor.

false if the target does not resolve. Immediate, but it reads the activation computed at the start of the stage, so a set_active queued during this stage is not reflected until the next one. A disabled object runs none of its own systems, so enabling it again has to come from another object.

This shadows SystemContext::is_active, which takes a world and an entity.

pub fn find_object(&self, name: &str) -> Option<ObjectId>

Finds an object by name: the first visible object with that name in the scene’s authoring order, or None.

The comparison is exact (case-sensitive). Disabled objects are found too. Immediate: objects spawned this stage are not there yet. Names are not unique, so prefer an ObjectRef field wired up in the inspector for objects you know at design time, and use find_object for lookups by convention ("Player", "Spawner"). It scans every named object, so look an object up once (in a start-up system or on the first frame) and keep the returned ObjectId instead of searching every frame.

§Examples
ⓘ
if !self.player.is_set() {
    self.player = ctx.find_object("Player").map(ObjectRef::new).unwrap_or(ObjectRef::NONE);
}

pub fn input_command(&mut self, command: InputCommand)

Queues any InputCommand: rebind, unbind, tune, reset, switch scheme, start or cancel a capture.

Queued (obj). Wrapped in ComponentCommand::Input and applied by the host at the end of the frame. Successful changes are saved to the player’s overrides file immediately, so they persist between runs. A request that names a scheme, action or slot that does not exist is logged and ignored; no error comes back.

The other input helpers here are shortcuts for common commands. Use this one for the rest: Unbind, ResetAction, ResetAll, SetScheme, SetAutoSwitch and CancelCapture.

pub fn rebind_with( &mut self, scheme: &str, action: &str, slot: BindingSlot, index: usize, source: InputSource, policy: ConflictPolicy, )

Binds source (a key, button or axis, as an InputSource) to an action.

scheme names the control scheme ("" is the active one) and action the action. slot picks which list of the action to edit (BindingSlot: its buttons, the parts of a composite axis, or the analog axes) and index the position in that list; the input there is replaced. policy decides what happens to other actions that already use this input (ConflictPolicy): Swap (the default) gives them the input this slot had, Steal takes it from them, Allow lets both keep it. Binding a stick to the analog X of a 2D action also binds its Y partner.

pub fn rpc(&mut self, name: &str, args: Vec<NetValue>, target: RpcTarget)

Sends a reliable RPC (a named call with arguments) that is not tied to an object.

Queued (host). Online this pushes ComponentCommand::NetRpc, exactly send_rpc with object: None and reliable: true. The play session does not handle it, so the host application sends it after the frame’s last stage. // before a `&mut` call such as `ctx.rpc`).
let asked: Vec<(u64, i64)> = ctx.rpcs_named("OpenDoor")

pub fn send_rpc( &mut self, object: Option<ObjectId>, name: &str, args: Vec<NetValue>, target: RpcTarget, reliable: bool, )

Sends an RPC with an explicit object, target and reliability: the general form behind rpc, rpc_unreliable and rpc_self.

object ties the RPC to an object (Some(id)) or leaves it global (None). Receivers see it as NetRpc::object, and rpcs_for_self lists the ones sent on the object a system runs on. RpcTarget::Owner goes to that object’s owner (the host when it is unowned or object is None). name is the string receivers match with rpcs_named; args are NetValues, read back in order with NetRpc::arg. reliable picks guaranteed in-order delivery or a single lossy datagram.

Queued (host). Online this pushes ComponentCommand::NetRpc. The play session does not handle it, so the host application sends it after the frame’s last stage. Receivers get it on the frame its packet arrives. When target includes the sending peer (All, Server on the host, Owner when you are the object’s owner, or the host for an unowned or absent object, Peer with your own id) a copy with from = your own peer id is delivered to you on the frame after you queued it.

Offline (no session, which includes a join that is still handshaking) nothing is sent. When target includes the local player (All, Server, Owner, or Peer with the id 0) a copy with from = 0 is queued as a local event and is readable through rpcs on the next frame; Others is dropped. This keeps single-player code paths working.

Limits. The host checks every RPC a client sends before relaying or delivering it. An RPC is dropped, and counted against the sender as a violation, when it exceeds the rate limit or the size limits (by default 16 arguments, 1024 bytes, a 256-byte name) or when its name has a permission rule (RpcRule) the sender does not satisfy. With the server’s strict_rpc_permissions on, a dedicated server treats unregistered names as owner-only, which a global RPC can never satisfy because it has no owner. A dropped RPC produces no error on the sender.

§Examples
ⓘ
// Tell the owner of a door (the host if nobody owns it) to open it, reliably, with the opener's id.
ctx.send_rpc(Some(door), "Open", vec![NetValue::from(ctx.local_peer() as i64)], RpcTarget::Owner, true);

pub fn ray_cast_at( &self, time: f64, origin: Vec3, dir: Vec3, max_dist: f32, ) -> Option<RewindHit>

Host only: tests a ray against the networked hitboxes posed as they were at session-clock time (lag compensation), ignoring this object.

Immediate. A read of the host’s recorded hitbox history. It returns the nearest RewindHit (object, point, distance, the time tested) within max_dist metres of origin along dir. dir need not be normalized, but a zero vector hits nothing.

§Returns

None when nothing is hit, when called offline or on a client (only the host records a history), when dir is zero, or when time is not a finite number. On a dedicated server, or with strict validation on, None also covers a time outside the rewind window (from the future, or too old): it is refused and counted instead of being clamped. Elsewhere such a time is clamped into the window. The window is the scene’s NetValidation::max_rewind (0.25 s by default, never more than HARD_MAX_REWIND); MAX_REWIND is only the default of a bare HitHistory.

§What is rewound

Only hitboxes: networked objects (NetworkObject with sync_transform on) that have a Character Controller capsule or a non-trigger Sphere, Capsule or Box Collider. The host records them once per frame, after the frame’s systems have run, with the pose the other peers are shown. World geometry and physics bodies are not rewound: compare distance with raycast to see whether a wall was in the way.

§Gotchas

Only this object is ignored, not the shooter’s avatar. A ray that starts inside a hitbox hits it at (or very near) distance 0, so exclude the shooter’s own objects with ray_cast_at_filtered, or use ray_cast_rewound, which works out the time on the server and excludes everything the shooter owns. time, origin and dir normally come from a client: check them against what the shooter’s avatar could have done.

§Examples
ⓘ
// Host: the client sent "Fire" with origin, direction and its `net_view_time` (8 bytes).
let shots: Vec<(Vec3, Vec3, f64)> = ctx.rpcs_named("Fire").filter_map(|rpc| {
    let (origin, dir) = (rpc.arg(0)?.as_vec3()?, rpc.arg(1)?.as_vec3()?);
    let seen_at = f64::from_le_bytes(rpc.arg(2)?.as_bytes()?.try_into().ok()?);
    Some((origin, dir, seen_at))
}).collect();
for (origin, dir, seen_at) in shots {
    let hit = ctx.ray_cast_at(seen_at, origin, dir, 100.0);
    let wall = ctx.raycast(origin, dir, 100.0);   // geometry is not rewound
    if let Some(hit) = hit.filter(|h| wall.is_none_or(|w| w.distance > h.distance)) {
        self.apply_damage(hit.object, 10);
    }
}

pub fn ray_cast_rewound( &self, shooter: u64, origin: Vec3, dir: Vec3, max_dist: f32, ) -> Option<RewindHit>

Host only: tests a ray against the hitboxes as shooter saw the world when it fired, with the time worked out by the server.

The time is the session clock now, minus the shooter’s measured round trip (PeerInfo::rtt_ms), minus the view delay it reported (PeerInfo::view_delay). It is always clamped into the rewind window and never refused, so a client cannot ask for a time of its own. This object and everything the shooter owns (its player and the props it holds) are ignored, so a shot cannot hit its own shooter.

Immediate. A read of the host’s recorded hitbox history. It returns the nearest RewindHit within max_dist metres of origin along dir.

§Returns

None when nothing is hit, when called offline or on a client (only the host records a history), when dir is zero, and when shooter is not a peer in the session (its latency is unknown). What is rewound, and what is not, is described on ray_cast_at: hitboxes only, so compare the distance with raycast for walls. origin and dir normally come from the client; on a dedicated server check them against the shooter’s avatar before trusting them.

§Examples
ⓘ
// Host: a client asked to fire. `rpc.from` is the connection the RPC arrived on, so it cannot be forged.

    .collect();
for (shooter, origin, dir) in shots {
    let hit = ctx.ray_cast_rewound(shooter, origin, dir, 100.0);
    let wall = ctx.raycast(origin, dir, 100.0);   // geometry is not rewound
    if let Some(hit) = hit.filter(|h| wall.is_none_or(|w| w.distance > h.distance)) {
        self.apply_damage(hit.object, 10);
    }
}

pub fn load_content(&mut self, source: impl Into<String>) -> ContentRequest

Loads a content package (a .zestenginepak world, avatar or prop) without placing it anywhere.

source is a file path (absolute, or relative to the working directory or the project’s asset root), an http:// URL, or a content id: the 64-digit hash of a package loaded earlier (ContentInfo::id). An https:// URL fails with a ContentEvent::Failed unless the game installed a fetcher that speaks TLS; the built-in one is plain HTTP.

Queued (host). Pushes ComponentCommand::Content. The play session does not handle it, so the host application hands it to the engine’s content manager after the frame’s last stage. Downloading, validating, unpacking and uploading to the GPU then run on a background thread over the following frames; nothing blocks the game. The returned ContentRequest is the handle every resulting event carries, so match it in content_events: zero or more ContentEvent::Progress, then exactly one of ContentEvent::Loaded or ContentEvent::Failed (with the reason). A package that is already loaded answers with Loaded straight away without fetching again, and two requests for the same source share one load but each get their own events.

Loading only keeps the package ready. spawn_content, spawn_avatar and enter_world load it first when needed, so call this to preload or to inspect the ContentInfo (name, author, kind, warnings) before committing. Free it with unload_content. Only hosts that run a content manager handle these requests (the player and the editor’s Play mode); a headless dedicated server ignores them and no event ever arrives.

§Examples
ⓘ
// Start the load and remember the request.
self.pending = Some(ctx.load_content("worlds/arena.zestenginepak"));

// On later frames, wait for its result.
for event in ctx.content_events() {
    match event {
        ContentEvent::Loaded { request, info } if Some(*request) == self.pending => self.show_title(&info.name),
        ContentEvent::Failed { request, error, .. } if Some(*request) == self.pending => self.show_error(error),
        _ => {}
    }
}

Loads a prop or avatar package (when it is not loaded yet) and adds one instance of it to the world at a world position and rotation.

The id is yours to store, but the object only exists when ContentEvent::Spawned arrives (its root is the same id), some frames later; until then lookups of that id find nothing. pub fn spawn_avatar( &mut self, player: impl Into<ObjectRef>, source: impl Into<String>, ) -> Option<(ContentRequest, ObjectId)>

Makes an avatar package the visual of player, replacing the avatar it wore before. Returns None (and queues nothing) when player is an unset reference.

Otherwise it works like spawn_content: it returns the request handle and the root id at once and completes later with ContentEvent::Spawned. It fails with ContentEvent::Failed when the package is not an Avatar, or when player is no longer in the scene by the time the package is ready. When the avatar is ready its root is parented under player at its origin, the player’s previous avatar is removed and freed, the player’s camera moves to the eye point of the avatar’s AvatarDescriptor, the player’s Character Controller capsule takes the descriptor’s body size (when the descriptor gives one), and skinned meshes get full-body IK (meshes with blend shapes also get face tracking and lip sync).

They fetch it from the http(s):// URL it was loaded from, or by content id when it is already in their cache, so an avatar loaded from a local file path only shows for peers that already have it.
