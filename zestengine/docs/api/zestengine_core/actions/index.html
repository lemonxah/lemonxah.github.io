Module actions 

Source
Expand description

Event/action bindings: “when this happens, call that function on that component, with these values”.

A component declares the functions it exposes (ActionDesc, through Component::actions) and the values other things may read from it (PropertyDesc, through Component::properties). An event source (Interactable, Trigger Events, UI Button, animation events) stores an EventActions of EventBindings. Firing a binding resolves the target object and component, evaluates each parameter from its ArgSource (constant, a property of another component, the instigator or the event payload), checks types, and queues a crate::ComponentCommand::InvokeAction that the engine applies after the pass, like every other mutation.

Everything here is egui-free and uses std types only, so plugin components can expose actions across the dylib boundary the same way they expose their data. The declaration shape (name, typed parameters, typed properties) is deliberately what a WASM export manifest can express (see EVT-2 in IMPLEMENTATION_PLAN.md).
